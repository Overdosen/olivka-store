# Admin Dashboard Analytics & Table Layout Refinements

Ця стаття описує покращення аналітичної логіки дашборду Olivka CRM та патерни побудови стійких адаптивних таблиць без наповзання елементів.

## Key Points

- **Унікальна ідентифікація клієнтів з гостьовими покупками**: Інтеграція підрахунку клієнтів безпосередньо з таблиці `orders` на основі унікального поєднання `email` та `phone`. Це забезпечує точний фінансовий та кількісний облік користувачів, які не мають акаунтів (гостей).
- **Стійкий адаптивний табличний макет**: Усунення перекриття кнопок дій (наприклад, ТТН) шляхом переходу від фіксованих ширин колонок до комбінації `whitespace-nowrap`, прагматичних відступів `pr-7` для інпутів та розділового адаптивного спейсера `w-full`.
- **Клієнтська фільтрація часових діапазонів**: Мінімізація навантаження на базу даних Supabase за рахунок локального фільтрування агрегованих даних замовлень на клієнті для періодів (7d, 30d, 90d, 1y).
- **Покращення UX рядків**: Перетворення стандартних табличних рядків `tr` на повноцінні інтерактивні елементи за допомогою React-хука `useRouter` для навігації при кліку на будь-яку область рядка.

## Details

### Ідентифікація клієнтів (Гості та Профілі)
Раніше метрика "Total Customers" відображала кількість користувачів лише з таблиці `profiles`. Це виключало гостьові замовлення, які є більшістю транзакцій в електронній комерції. Нова логіка аналізує масив замовлень, збираючи унікальні контактні дані:
```javascript
const uniqueCustomers = new Set();
orders.forEach(order => {
  const email = order.email?.trim().toLowerCase();
  const phone = order.phone?.trim().replace(/\D/g, "");
  if (email) uniqueCustomers.add(`email:${email}`);
  if (phone) uniqueCustomers.add(`phone:${phone}`);
});
```

### Стійкі адаптивні таблиці
При використанні інтерактивних елементів в одній клітинці (наприклад, введення ТТН + кнопка оновлення) виникали проблеми наповзання контенту на суміжні стовпці при зменшенні ширини екрана. Рішенням став паттерн:
```jsx
<td className="w-1 whitespace-nowrap px-4 py-3 text-right">
  {/* Вміст, який ніколи не буде переноситися чи ламатися */}
</td>
```
Замість спроб зафіксувати точну ширину кожного елемента, більшість колонок отримують мінімальну ширину `w-1` з властивістю `whitespace-nowrap`, а одна гнучка колонка виступає у ролі буфера, займаючи залишок ширини.
