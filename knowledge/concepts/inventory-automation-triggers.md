# Автоматизація залишків та складський облік

Для Store Olivka реалізовано надійне керування складом, що поєднує миттєве резервування при чекауті, базу даних Supabase (тригери/прапорець `is_stock_deducted`) та автоматичне відновлення залишків при поверненні статусу.

## Ключові правила списання та відновлення товарів:

1. **Чекаут (Оформлення замовлення покупцем):**
   - При оформленні замовлення клієнтом товари списуються зі складу **одразу** (навіть у статусі `new` / `pending_payment`), щоб уникнути оверсейлу.
   - Полю `is_stock_deducted` у таблиці `orders` присвоюється значення `true`.

2. **Тригер бази даних `trigger_on_order_paid`:**
   - Перевіряє статус замовлення. При переході в `paid` списує товари зі складу (`products.stock` та JSONB-поле `products.sizes`), якщо `is_stock_deducted` досі `false`.
   - Гарантує списання навіть при ручній зміні статусу в адмінці чи через LiqPay.

3. **Повернення залишків при редагуванні статусу (`paid` -> `new`):**
   - При зміні статусу із виконаного/оплаченого назад на `new` через адмін-панель викликається `/api/admin/orders/restore-stock`.
   - Товари (включаючи компоненти боксів `bundle_items`) **повертаються на склад**, а `is_stock_deducted` скидається в `false`.

4. **Індикатор стану на складі у картці замовлення (`/admin/orders/[id]`):**
   - У блоці «Статус та відправка» відображається плашка складського стану:
     - **`📦 Стан на складі: Списано`** (коли `is_stock_deducted == true`).
     - **`🔄 Стан на складі: Повернуто на склад`** (коли `is_stock_deducted == false`).
   - Після кожної зміни статусу картка замовлення робить свіжий `select` із Supabase, щоб плашка оновлювалася миттєво в режимі реального часу.
